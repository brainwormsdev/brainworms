# Talk to the Worm

One live simulation of a real marine worm larva's nervous system (the published *Platynereis dumerilii* whole-body connectome). The server runs the only worm; every visitor sees the same activity, and anyone can send it a message (shown to its eyes as light) or poke it.

## Commands

- `npm install` then `npm start` → http://localhost:3000
- `npm run dev` → restart on file changes
- `npm test` → unit tests + a two-viewer server test + an exact replay of the server's log. Run before every commit.
- `npm run replay -- <events.jsonl | https://site/log/current.jsonl>` → re-run a live log and check every published summary.

## Layout

- `shared/` runs in Node **and** the browser (served at `/shared/`). No Node or DOM APIs here.
  - `sim.js` firing-rate model on the wiring. `PARAMS` are shown on the site.
  - `worm.js` `WormCore`: sim + message queue + pokes + per-stimulus summaries. Pure and deterministic.
  - `text.js` + `glyphs.js` message → pixel columns → photoreceptor input. Identical on server and client.
  - `roles.js` which cells are eyes, touch sensors, muscles, cilia; readout maths.
- `server/server.js` http static server + WebSocket `/live`, 30 steps/s loop, 15 fps binary frames, feed, rate limits, admin, event log.
- `server/moderation.js` link / wallet-address / blocklist rejection, profanity censoring, token-bucket limiter.
- `public/` the page (`index.html`, `style.css`, `app.js`). Falls back to a local worm when the connection is down.
- `data/wiring.json` generated by `scripts/build-data/build_wiring.py` from the lab's repo (see README). Do not hand-edit.
- `config/blocklist.txt` owner-editable rejected phrases.

## Protocol (`/live`)

Client → server JSON: `{t:'say', text}`, `{t:'poke', cells:[touch-cell ids]}`.
Server → client JSON: `hello`, `queued`, `start`, `poke`, `done`, `watchers`, `hide`, `feed`, `error`.
Server → client binary frame: byte 0 = 1, bytes 1–4 = step (uint32 LE), then one byte per cell (activity × 255).

## Rules

1. **Honesty is the product.** Never change the wiring, add connections, or add per-synapse weights. Anything that changes how the model behaves must also update the "Simplified" and "What you see" sections in `public/index.html`. Don't write copy that claims the worm reads, understands, predicts prices, or chooses anything.
2. **Keep `shared/` deterministic.** No `Math.random`, `Date`, timers or I/O in `shared/`. If you change `shared/sim.js`, `shared/worm.js` or `shared/text.js` in a way that changes results, bump `v` in the server's boot log line so old logs aren't replayed against new code.
3. **One process.** The worm lives in server memory. Never run more than one instance (no horizontal scaling); that would create several different worms.
4. **Keep the scam filters.** The chat must never accept links or wallet/contract addresses. The official contract, if any, is only shown from `SITE_CONTRACT`.
5. **Keep the attribution.** The data is CC BY 4.0 (Verasztó et al., eLife 2025, Jékely lab). The footer credit and "not affiliated" line stay.
6. No build step and no frontend framework. Plain ES modules. Keep dependencies minimal (`ws`, `obscenity`).
